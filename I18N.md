# Spanish UI (FORJA2.0)

The app ships in Spanish. English strings stay in the source and act as the lookup keys, so every string comparison, test fixture and Liftoscript identifier keeps working unchanged.

## How a string becomes Spanish

`Translate_text` in `src/i18n/translate.ts` looks a string up in `esCatalog` and returns the original when there is no entry. It preserves the whitespace around a JSX text fragment, so `" Save "` renders as `" Guardar "` and inline spacing survives.

`Translate_children` in `src/i18n/translateChildren.tsx` maps the string children of a React node. `Text` and `TextRaw` in `src/components/primitives/text.tsx` call it, which covers the 243 files that render through the app's text primitive. Pass `noTranslate` on a `Text` that renders user-entered data.

The web pages render plain DOM elements instead of `Text`, so their JSX text is wrapped in `Translate_text("…")` in the source. That is a compile-time choice: nothing at runtime guesses whether a string is a label or a value.

Other call sites: `placeholder` in `src/components/primitives/textInput.tsx`, `label` and `placeholder` and error messages in `src/components/input.tsx`, option labels in `src/components/primitives/select.tsx`, every alert in `src/utils/dialog.ts` and `src/utils/dialog.native.ts`, every menu in `src/utils/actionSheet.native.ts`, and `<title>` plus the `og:` meta tags in `src/components/page.tsx`.

## The catalog

`src/i18n/es/` holds one file per area: `ui.ts`, `settings.ts`, `pages.ts`, `content.ts`, `errors.ts`, `tour.ts`, `fragments.ts`, `muscles.ts`, `exercises.ts`, `programs.ts`, `brand.ts`. `index.ts` merges them; a key defined twice takes the value from the later spread.

Keys are the decoded text, not the source text. The JSX transform turns `&nbsp;` into ` ` before the string reaches a component, so the key is `"Reps range: "`.

Exercise names are translated for display only. `Exercise_searchNames` and `Exercise_filterExercises` in `src/models/exercise.ts` search through `Translate_searchableName`, which matches the English name and the Spanish one, so typing "sentadilla" and typing "squat" both find Squat. The name written into a program stays English, because Liftoscript resolves exercises by that name.

## Coverage

`npx ts-node -T scripts/i18n-coverage.ts` prints how many UI strings have a catalog entry. Add `--list` to print the ones that do not, with the file each comes from.

Coverage is 98.4% of 1398 strings. What the report still lists is brand names, email addresses, weights like `185lb`, and code identifiers like `state.name` — none of those should be translated.

## What is still English

The long-form exercise instructions in `exercises/*.md`, about 127,000 words, feed `src/models/exerciseDescriptions.ts`. They render only on the public `/exercise/…` SEO pages, never inside the app.

`CHANGELOG.md`, `docs/content/*.md` and `blog/posts/*.md` carry the FORJA2.0 name but their prose is English.

## Renaming

The display name is FORJA2.0 in `app.json` (`displayName`), `manifest.webmanifest`, `android/app/src/main/res/values/strings.xml` and `CFBundleDisplayName` in `ios/Liftosaur/Info.plist`.

Three identifiers keep the old name on purpose, because changing one without the others breaks the build: the React Native component name in `app.json` (`name`), `withModuleName` in `ios/Liftosaur/SceneDelegate.swift` and `getMainComponentName` in `android/app/src/main/java/com/liftosaur/www/twa/MainActivity.kt`. The bundle ids, the `liftosaur.com` domains, the API hosts and the storage keys are unchanged too, so sync, sign-in and deep links keep working.
